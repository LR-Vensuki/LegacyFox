# LegacyFox: отдельный процесс для страниц

## Зачем
- У 32-битного приложения на iOS 6 есть 768 МБ адресного пространства ниже
  shared region (0x30000000). После урезания в 1.0.0~beta3 на bsky.app
  свободно ~195 МБ, но куча страницы (tag 0, 230–250 МБ на ленте) растёт с
  прокруткой, а XUL (124 МБ), артворк UIKit (37), ICU (18.5), эмодзи (24) и
  наш JIT (24) убрать нельзя.
- Gecko, UIKit и касания делят главный поток: пока сайт выполняет JS, прокрутка
  стоит (dzen.ru: замирания по 1.5–2.5 с).
- Процесс содержимого получает свои 768 МБ (UIKit, артворк и драйвер GPU в нём
  не нужны), а касания и APZ остаются в родителе и не ждут JS.

## Что проверено
- `tools/spawnprobe` на iPhone 4S (iOS 6.1.3), от root и от mobile: свой
  `bootstrap_check_in` с динамическим именем, `posix_spawn` дочернего процесса,
  `bootstrap_look_up` в ребёнке и передача его task port родителю работают.
  Это ровно схема macOS-запуска Gecko (MachHandleProcessCheckIn /
  MachChildProcessCheckIn). Не проверено из процесса, запущенного SpringBoard.

## Шаги
1. **Запуск.** `IosProcessLauncher::DoLaunch` под `MOZ_IOS_LEGACY` сейчас
   отказывает. Сделать как `MacProcessLauncher`: в `DoSetup` —
   `bootstrap_check_in` (код из ветки XP_MACOSX около строки 1290
   `ipc/glue/GeckoChildProcessHost.cpp`), в `DoLaunch` —
   `PosixProcessLauncher::DoLaunch` (posix_spawn `plugin-container`) и
   `MachHandleProcessCheckIn`. Окружение: передавать `LF_*` и `MOZ_*`.
2. **Ребёнок.** `toolkit/xre/nsEmbedFunctions.cpp`: проверка `MachChildProcessCheckIn`
   есть только под XP_MACOSX — открыть для MOZ_IOS_LEGACY (без песочницы).
   `plugin-container` подписать entitlements оболочки (dynamic-codesigning для
   JIT), crashlog в ребёнке тоже.
3. **Префы.** `browser.tabs.remote.autostart=true`, `dom.ipc.processCount=1`,
   fission выключен, GPU-процесса нет (компоновщик в родителе), сокет-процесса
   нет. Проверить пути GeckoView для удалённого `<browser>` (как на Android).
4. **Отрисовка.** Содержимое шлёт display list в WebRender родителя;
   SWGL/GPU-путь и IOSurface остаются в родителе. Миниатюры вкладок сейчас
   читают слой IOSurface в родителе — должно остаться как есть.
5. **Память.** Сторож адресного пространства (nsAppShell) — в каждом процессе
   свой; в ребёнке он даёт LowMemory и при критическом уровне просит родителя
   закрыть страницу. Физическая память: второй процесс — это ещё ~40–60 МБ
   резидентно на 512 МБ; падение ребёнка (jetsam) — это «вкладка упала,
   нажмите для перезагрузки», а не вылет браузера.
6. **Проверка.** run.sh/lfvm на обоих PID; bsky 150 с, dzen с замером замираний
   прокрутки (цель: касания без задержки, ≥ 20 кадров/с), 16 вкладок подряд,
   вход в аккаунт Mozilla, загрузки, пароли.

## Риски
- Код межпроцессного GeckoView на iOS не проверялся: могут быть ветки XP_IOS,
  завязанные на ExtensionKit/BrowserEngineKit.
- Два процесса на 512 МБ устройствах: физической памяти может не хватить
  раньше, чем адресного пространства. Запасной вариант — оставить один процесс
  выключателем в настройках.
- Оценка: несколько дней работы.
